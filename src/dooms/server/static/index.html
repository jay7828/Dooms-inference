One real run, answer by answer

Everything below is copied from a recorded episode: Claude Sonnet 4.5 on Amazon Bedrock, asked to "put the bottle into the box".

  1. Scoutreads the scene
  2. Composerwrites the recipe
  3. Tunerpicks the numbers
  4. Spotterfinds the points
  5. The armdoes it
Scout said

The bottle is upright. Six steps.

"The bottle is standing upright on the table to the right of the box. The box appears empty with no obstructions inside. The bottle's cap end is at the top, making it suitable for top-down grasping."

  1. Approach bottle for pre-grasp
  2. Grasp the bottle
  3. Lift the bottle up
  4. Move over the box
  5. Lower the bottle into the box
  6. Release and retract
Composer wrote

A recipe per step, with blanks for the numbers

For the first step it defined a skill called approach_bottle_pregrasp and asked the Spotter for one keypoint, the centre of the bottle's cap.

# subtask 1: Approach bottle for pre-grasp
[p1] PosAlign(eef_tcp, bottle_cap, axis=x, o_x)
[p1] PosAlign(eef_tcp, bottle_cap, axis=y, o_y)
[p1] PosAlign(eef_tcp, bottle_cap, axis=z, o_z)
[p2] AxisAlign(eef_z, bottle_cap_normal, o_theta)
Tuner set

Every blank, with a reason

o_z0.12 mHover 12 cm above the bottle cap for pre-grasp approach
o_theta180°Gripper points down onto upward-facing cap surface
o_d-0.015 mFingertip centre goes half the cap height below the cap top to centre pads on the cap
f3 NGentle contact force threshold for placing the bottle
Spotter pointed

Two pixels become two places in space

bottle_cap at pixel 377, 1882.2 mm from the simulator's ground truth
box_inside at pixel 265, 28529 mm off, still inside the tray

It also has to cope when things go wrong

In this recorded run the bottle was knocked over beside the box. The Composer asked for a keypoint that is in no object list, a free spot on the table, and the Spotter found one. A grasp was missed along the way and the scene was grounded again before the run finished.

What we are studying

Behaviour as aligned axes, not trajectories

A skill is a short list of controllers, each aligning one point or axis with another, or pushing until contact. The runtime stacks them by priority.

# subtask 5: Lower the bottle into the box
[p1] PosAlign(bottle_cap, box_inside, axis=x, offset=+0.000 m)
[p1] PosAlign(bottle_cap, box_inside, axis=y, offset=+0.000 m)
[p1] Force(axis=-z, contact>=3.0 N)
[p2] AxisAlign(eef_z, box_inside_normal, angle=180 deg)

Two very different arms

A 7-joint Franka Panda and the 5-joint SO-ARM101, which has no force sensor. Same pipeline, a different robot profile.

A skill library that grows

Recipes that succeed are stored by role, not by object name, and offered again with the numbers that worked.

Recovery before replanning

A failed subtask first triggers a second look at the scene. Only if that fails does the Scout plan again from where things now lie.

Inference moved into the browser

The Python stack was ported to TypeScript and a web worker. Claude is called from the page with your own AWS credentials, and skills are kept in IndexedDB. Hosting is static files.
